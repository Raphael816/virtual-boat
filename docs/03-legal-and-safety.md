# 03. 実際のお金での賭けを検討する前に確認すべき事項

> **前提**：本リポジトリのMVPは仮想コイン（購入不可・換金不可・景品交換不可）のデモモードだけを実装しています。
> 以下は、実際のお金を扱う機能を **検討するかどうかを判断するため** のチェックリストです。法的助言ではありません。
> 必ず提供地域ごとの専門家（弁護士・規制当局）に確認してください。**確認と許認可が済むまで、入金・出金・実際のお金での賭けは実装しません。**

## A. 法令・許認可

| 項目 | 確認内容 |
|---|---|
| 提供地域の特定 | どの国・州・地域のユーザーに提供するのか。ジオブロッキングの要否 |
| 日本での位置づけ | 刑法の賭博罪・富くじの規定。ボートレースの勝舟投票券はモーターボート競走法に基づく施行者に限られるため、**民間が架空レースに金銭を賭けさせることは原則として認められないと考えられる**。日本向けに実際のお金を扱うことは想定しない前提で、法務の見解を得る |
| 海外のライセンス | 例：英国（Gambling Commission、バーチャルイベントのベッティング）、マルタ（MGA）、米国（州ごとの規制）など。ライセンスの種類・取得費用・現地法人・現地サーバーの要件 |
| 仮想コインの設計 | 有償販売すると資金決済法上の前払式支払手段などに該当する可能性がある。景品・換金があると賭博や景品規制の問題が生じうる。**MVPでは「購入不可・換金不可・譲渡不可・景品なし」を維持する** |
| 広告・表示 | 誇大な表現、未成年者向けの広告の禁止、勝利を保証する表現の禁止、各地域のギャンブル広告規制 |
| プラットフォームの規約 | App Store・Google Playの実際のお金を扱うギャンブル規約、模擬ギャンブル（シミュレーテッド・ギャンブリング）の年齢レーティング |
| 個人情報 | 個人情報保護法、GDPRなど。本人確認の書類や利用履歴の保管期間 |
| 知的財産 | 実在の選手名・レース場名・団体名・ロゴ・映像・実況音声は、権利処理なしに使用しない（MVPはすべて架空。水面の形は公開情報を参考にした非公式の再現で、出典は [05](./05-venue-reference.md)） |

## B. 本人確認・年齢確認・マネーロンダリング対策

- 年齢基準は提供地域の法令に従う（多くの地域では18歳または21歳以上）。自己申告では不十分であり、公的書類とeKYCによる確認が必要
- KYC（本人確認）、継続的な顧客管理、PEPs・制裁リストの照合
- AML/CFT：入金元と出金先の一致、取引のモニタリング、疑わしい取引の届出の体制
- 複数アカウントや不正の検知、ボーナスの悪用対策

## C. 決済・資金管理

- 決済代行事業者の審査（ギャンブル関連の加盟店として扱えるかどうか）
- 顧客資金の分別管理（信託・分別口座）、資金を保全する仕組み
- 出金手続き、チャージバック、手数料
- 会計：複式簿記の台帳、冪等性、照合（リコンシリエーション）、監査法人による監査

## D. 公正性・技術監査

- RNG（乱数生成器）とゲームロジックの第三者認証（例：GLI-19などの試験機関の基準）
- 控除率と還元率の表示義務
- seed の管理（KMS/HSM）、権限の分離、変更管理、監査ログの改ざん防止（WORM）
- 障害時の扱い（レースの中止・払戻・返還）を利用規約に定める
- フライング・出遅れによる返還欠場、完走艇不足による不成立の返還ルールを明示する（デモでは実装済み：[02](./02-architecture.md) §4.5）

## E. 責任ある利用（既に試作に組み込んだもの＋本番で追加するもの）

| 機能 | MVP | 本番で追加するもの |
|---|---|---|
| 年齢確認 | 自己申告 | eKYCによる確認 |
| 投票上限（1レース／1日） | ✅（コードはあるが、デモ設定でオフ） | 入金上限（日・週・月）。引き上げは冷却期間の後に反映 |
| 損失額の通知 | ✅ 1日の損失上限（デモ設定でオフ） | 週・月単位、強制的な停止 |
| 利用時間のリマインダー | ✅ | リアリティチェック（経過時間と収支を強制的に表示） |
| 一時休止 | ✅ 24時間／7日（デモ設定でオフ） | 最大で数か月 |
| 自己排除 | ✅ 端末内（デモ設定でオフ） | 全アカウントに適用。各国の自己排除登録制度との連携 |
| 相談窓口の案内 | 文言のみ | 各地域の依存症相談窓口へのリンク |
| 行動分析 | — | リスク行動の検知と介入（取り戻そうとする賭け方、深夜の連続利用など） |

## F. 運用体制

- コンプライアンス責任者、MLRO（マネーロンダリング対策の責任者）、サポート窓口（24時間体制の要否）
- インシデント対応、規制当局への報告
- 定期的な監査とポリシーの見直し

---

**結論（試作段階の方針）**：実際のお金の機能は、上記A〜Fを法務と運用担当が確認し、必要な許認可を取得したあとに、別のプロジェクトとして設計します。それまでのコードベースには入金・出金・決済のAPIや画面を一切含めません。
